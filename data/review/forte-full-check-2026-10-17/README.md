## Как используется

`python -m data_prepare.review_import` (в compose `reference/` только на чтение — `--reference` на записываемый путь):

- `reference/norms_review.yaml` — 34 пункта с ключами как в `norms.yaml` (`n231_p20`, `n14_p8`, `n53_p71`, `forte_online2025_p35_4`…). Выверенные вручную `norms.yaml` главнее, недостающие поля (`requirement`, `limits`) берутся отсюда;
- `reference/video_review.yaml` — итог по каждому из 42 файлов;
- `reference/violations_unreviewed.yaml` — блок `review`; `type` из проверки при `supported` / `probable`, при `insufficient` — «неясно», прежний — в `prev_type`.

Выводы аудита в правилах `reference/scenarios.yaml`:

- косвенные и условные основания — поле `basis` (`relation: косвенно / условно`), на статус события не влияют: сейф и ключ — №231 п.80; посторонний — №14 пп.8, 16; компьютер без блокировки — №53 п.71 (автоблокировка через 30 мин, коротким роликом не проверяется);
- ForteBank п.35(4) / 35(3) к кассиру не привязан: это правила для клиентов Онлайн-платформы, в X-28 система и сессия не установлены;
- телефон при клиенте — предупреждение без нормы: п.12 допускает средства связи без фото- и видеофиксации;
- посторонний во время обслуживания — без ссылки на п.20 (прямого запрета двух посетителей в нём нет);
- X-1 — норма не ставится, пп.59/61 не установлены.

Основания попадают в описание события и ответ жюри («основание (условно): …»), требование прямого норматива — в каталог типов интерфейса. `decision.eval` печатает статус проверки у каждого видео и итог по статусам.
